financialHistory — synthesised from record snapshots

// Bridge scans gr_udyami_records for all records belonging to this entrepreneur
// and builds a 2-entry time-series at minimum:
function buildFinHistory(allRecords, udyamiId) {
  const recs = allRecords
    .filter(r => r.udyamiId === udyamiId || r.name === name)
    .sort((a,b) => new Date(a._savedAt) - new Date(b._savedAt));

  const baseline = recs.find(r => r._formType === 'baseline') || recs[0];
  const latest   = recs[recs.length - 1];

  const entries = [];
  if (baseline) entries.push({
    month: baseline._savedAt?.slice(0,7) || '—',
    sales: baseline.sales || 0, expenses: baseline.expenses || 0
  });
  if (latest && latest !== baseline) entries.push({
    month: latest._savedAt?.slice(0,7) || '—',
    sales: latest.sales || 0, expenses: latest.expenses || 0
  });
  return entries;
}

visits — flat records → structured array

function buildVisits(allRecords, udyamiId, name) {
  return allRecords
    .filter(r =>
      (r.udyamiId === udyamiId || r.name === name) &&
      r._formType === 'visit'
    )
    .sort((a,b) => new Date(a.visitDate) - new Date(b.visitDate))
    .map(r => ({
      date:     r.visitDate,
      type:     r.visitType || 'Routine',
      officer:  r.officerName || '—',
      duration: r.duration || '—',
      notes:    [r.officerNote, r.flagReason, r.dropoutReason]
                  .filter(Boolean).join(' | '),
      actions:  r.needs || []
    }));
}

8 — Recommendations

Fix shakti/swasthya bridge to pass raw score arrays (not estimates)

Update bridgeToEntDashboard() in app.html to read u.shaktiScores and u.swasthyaScores arrays directly. Ensure submitForm('baseline') in io_form_v12.html stores these as arrays (keys shaktiScores and swasthyaScores) alongside the computed totals (shakti, swasthya). This is the highest-priority fix — the current estimation produces incorrect capability profiles.

Add GSTy / FSSAI / Udyam registration fields to Field Report (v13)

The entrepreneur dashboard shows business registration status (GST, FSSAI, Udyam/MSME, CIBIL). Currently these are absent from the form. Adding simple Yes/No checkboxes to Field Report Section 1 would enable accurate KYC object construction in the bridge without any approximation.

Add NIC code field to Baseline (v13)

Dashboard schema includes nic: {code, description} for industry classification. A simple text input (or dropdown of common NIC codes for rural enterprises) in Baseline Section B would complete this field. Bridge currently passes {}.

Add Hindi name field to Baseline (v13)

nameHindi is rendered prominently in the entrepreneur dashboard header. An optional Devanagari text input in Baseline Section A would populate it. Bridge currently passes "".

Standardise gender value casing

Form stores lowercase "male"/"female"/"other"; dashboard displays "Male"/"Female"/"Other". Either capitalise at form submit or add a one-line normalisation in the bridge: gender: (u.gender||'').charAt(0).toUpperCase() + u.gender.slice(1).

Document enterpriseType normalisation table

The form's enterprise type options (e.g. "Agri / Agri-Allied", "Manufacturing", "Services") differ from the dashboard's array values ("Agri & Allied", "Manufacturing", "Services"). Maintain a lookup map in the bridge or normalise the form values to match the dashboard expected set.

Long-term: unify localStorage key & schema

The cleanest resolution is to migrate both files to a shared schema under a single key (e.g. gr_records_v2) with a well-defined entrepreneur object. Until then, the bridge in app.html is the recommended integration path. Document the bridge as the canonical translation layer so future form changes are reflected in one place.
