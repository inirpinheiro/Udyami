Section 3 — Fields Missing from Form (Dashboard needs but form doesn't capture)
3
Dashboard Fields with No Form Counterpart — Require Form Enhancement
❌
bmc — Business Model Canvas Completion Status
Dashboard shows "done" or "pend" per udyami. The Visit Form (v11) has no dedicated BMC status field. Assessment Form Section E captures a 1–4 rubric score (bt_bmc), but this is a periodic form (4M/1Y/2Y/3Y) — not a regular visit field. The dashboard requires current BMC status that should be updated each visit. Solution needed: Add a "BMC Status" select field to the Visit Form.
❌
ue — Unit Economics Completion Status
Same gap as BMC. Assessment Section E has bt_ue rubric, but Visit Form v11 has no Unit Economics status field. Officers need a way to update UE completion status during regular visits without filling the full Assessment form. Solution needed: Add UE completion status to the Visit Form.
❌
bp — Business Plan Completion Status
Same gap as BMC and UE. Assessment Section E has bt_bp rubric, but Visit Form v11 has no Business Plan status field. The dashboard shows this as a progress indicator for all 33+ udyamis, but it can only be updated via the periodic Assessment — creating stale data between assessments. Solution needed: Add BP completion status to the Visit Form.
❌
flag — At-Risk Flag (boolean)
The dashboard displays a red "⚑ Flag" indicator for udyamis requiring urgent attention (6 flagged in sample data). No form panel in v11 provides a way to set this flag. Currently must be manually toggled in the dashboard's hardcoded data. Officers need to be able to flag a concern during a visit. Solution needed: Add a "Flag this entrepreneur" toggle or checkbox to the Visit Form officer sign-off section.
❌
dropout — Programme Dropout Status (boolean)
Dashboard shows dropout udyamis with greyed-out rows and "DROPOUT" label, and excludes them from active counts and GMV calculations. No form panel in v11 captures dropout status — not even an exit form or closure reason field exists. This is a critical gap as dropout status fundamentally changes all reporting metrics. Solution needed: Add a "Mark as Dropout / Programme Exit" option to the Visit Form or create a separate Exit Form.
Section 4 — Recommendations for Form v12+
4
Prioritised Recommendations to Close Mapping Gaps
High Priority
Add BMC, Unit Economics, and Business Plan completion checkboxes to the Visit Form. A simple 3-field status group (e.g. "BMC: ☐ Not started / ☐ In progress / ☑ Complete") added to the Visit Form officer section would allow regular status updates without requiring the full Assessment form. This closes the largest data gap — 3 dashboard fields are currently unreachable.
High Priority
Add a "Mark as Dropout / Programme Exit" option to the Visit Form. A simple toggle or select field (with an optional reason: e.g. "Migration", "Family constraint", "Business closed", "Voluntary exit") in the Visit Form sign-off section would allow officers to officially record dropout status. Without this, the dashboard's active count and GMV figures are inaccurate for churned cohorts.
Medium Priority
Add a "Flag this entrepreneur — needs urgent attention" toggle to the Visit Form officer sign-off section. A single checkbox labelled "⚑ Flag for review" with a brief reason field would allow the flag indicator in the dashboard to be set through data collection rather than manually. Recommended for visit forms, not baseline.
Medium Priority
Add a "KYC Complete" summary select field to Field Report Section 1. Currently, KYC status must be derived from 21 individual document checkboxes, which is error-prone. A single officer-assessed summary field ("Overall KYC Status: Pending / Substantially Complete / Fully Complete") added after the checklist would provide the binary done/pend value the dashboard needs, while keeping the detailed checklist for audit purposes.
Medium Priority
Standardise village / GP naming in Baseline Section A. Currently, the village field is a free-text input — meaning "Baghli", "baghli", and "Baghli GP" can all refer to the same location but won't match in dashboard filters. Options: (a) Add " GP" suffix automatically on save, (b) Replace free-text with a dropdown pre-populated from the block's known GP list (available from loc-block selection), or (c) Enforce a standard format hint. Prevents duplicate village entries in the dashboard filter.
Low Priority
Add an explicit "Udyami ID" lookup field to Field Report, Visit, and Assessment forms. Currently these forms have a free-text Udyami ID input with no validation or lookup. If the officer misremembers or mistyped the ID, the merge will create duplicate records instead of updating the correct one. A lookup/autocomplete from stored baseline records would prevent orphaned records.
Low Priority
Consider splitting salesBL (baseline sales) from sales (current sales) at the data schema level. Both use the same form field b-sales — but salesBL must be frozen at first baseline submission while sales updates with each visit. The integration layer must handle this timing logic explicitly. Documenting this as a frozen-at-first-submission field in the schema would prevent future confusion.
